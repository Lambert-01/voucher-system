1. Executive Summary
This document describes a complete production-ready Voucher Management System for N.HONEST Supermarket. 
The system is designed for gift vouchers and company monthly vouchers where an organization or person buys a 
fixed shopping value for beneficiaries. Each beneficiary receives a printed voucher card with a QR code. The 
cashier scans the card during shopping, enters the amount consumed, and the system deducts it from the 
remaining balance.
The system should be affordable, secure, easy for cashiers, and clear for the boss. It can operate as a separate 
voucher system first, then later be integrated into the main supermarket POS.
Main Requirement Implementation Direction
Gift voucher support Each voucher has original amount, remaining balance, status, and 
usage history.
Company monthly vouchers Vouchers are grouped in monthly company batches, for example 
IOM June 2026.
Printable cards System generates professional cards with QR code, voucher 
number, EVA ID, amount, client name, logo, stamp, and contact info.
Cashier operation Cashier scans card, views balance, enters amount used, and 
confirms redemption.
Boss report Boss views monthly totals, company usage, remaining balances, and 
cashier activity.
Production security Role-based access, audit logs, transaction locking, no manual 
balance editing by cashier.
2. Business Problem and System Objective
Current manual voucher operation requires printed cards and client files. This works temporarily, but it creates 
risks: double use, wrong balance calculation, missing signatures, and slow reporting. A digital system solves these 
issues while keeping the card-based process familiar to customers.
2.1 Business Scenario
Example: A company buys 50 vouchers of 20,000 RWF each and gives them to employees. Each employee comes 
to the supermarket and consumes part or all of the voucher amount. The system tracks every use and the 
remaining balance.
Term Meaning in the System
Voucher value Original amount loaded on a customer voucher.
Balance Remaining amount after customer purchases.
Beneficiary / Client Person who receives and uses the voucher.
Company Organization that buys vouchers for beneficiaries.
Batch Group of vouchers bought for a month or program.
Redemption The act of using part or all of a voucher during shopping.
2.2 Objectives
 Allow companies to buy monthly voucher batches.
 Register each beneficiary with a unique voucher number and optional EVA ID.
 Generate QR code cards directly from the system for printing.
 Allow cashier to scan cards and deduct shopping amount from balance.
 Prevent fraud by controlling permissions and logging all actions.

5. Full Voucher Workflow
1. Company buys vouchers for a month or program.
2. Admin creates a company record if it does not exist.
3. Admin creates a voucher batch for that company and month.
4. Admin imports beneficiaries or creates vouchers one by one.
5. System generates voucher numbers and QR codes.
6. System generates printable voucher cards.
7. Customer comes to the supermarket with the card.
8. Cashier scans QR code or enters voucher number manually.
9. System displays customer details and current balance.

7. Voucher Status and Business Rules
Status Meaning Can Be Redeemed?
active Voucher has full balance and can be used. Yes
partially_used Voucher has been used before but still has 
balance. Yes
used Balance is zero. No
blocked Temporarily stopped by admin/boss. No
expired Voucher period ended if expiry is enabled for 
a batch. No
cancelled Voucher created wrongly or cancelled. No
7.1 Core Business Rules
 A voucher number must be unique.
 A voucher belongs to one batch and one beneficiary.
 A voucher balance cannot go below zero.
 A cashier cannot redeem a voucher that is used, blocked, expired, or cancelled.
 Every redemption must create a transaction record.
 Cashiers cannot edit voucher balance directly.
 System must show previous balance, amount used, and new balance after every redemption.
 If new balance becomes zero, status must become used.
 If voucher is used but balance remains, status must become partially_used.
 Boss and admin must be able to review transaction history at any time.

10. Cashier Scanning and Redemption Logic
For fastest production, use a USB QR scanner. It behaves like a keyboard and types the voucher number into a 
focused input field. A browser camera scanner can be added later.
Step Cashier Action System Action
1 Open scan page Display input field with autofocus.
2 Scan QR code Voucher number appears in input.
3 Submit search System fetches voucher and validates 
status.
4 Enter shopping amount System checks amount is not greater than 
balance.
5 Enter receipt number System saves reference to POS receipt.
6 Click Redeem System deducts balance and saves 
transaction.
7 Show result System displays previous balance, amount 
used, and new balance.
Core PHP redemption function
<?php
function redeemVoucher(PDO $pdo, int $voucherId, float $amountUsed, string $receiptNo, int $cashierId): array
{
    try {
        $pdo->beginTransaction();
        $stmt = $pdo->prepare("SELECT * FROM vouchers WHERE id = ? FOR UPDATE");
        $stmt->execute([$voucherId]);

        $voucher = $stmt->fetch(PDO::FETCH_ASSOC);
        if (!$voucher) {
            throw new Exception("Voucher not found.");
        }
        if (!in_array($voucher['status'], ['active', 'partially_used'])) {
            throw new Exception("Voucher is not usable.");
        }
        $previousBalance = (float)$voucher['balance'];
        if ($amountUsed <= 0) {
            throw new Exception("Amount must be greater than zero.");
        }
        if ($amountUsed > $previousBalance) {
            throw new Exception("Insufficient voucher balance.");
        }
        $newBalance = $previousBalance - $amountUsed;
        $newStatus = $newBalance <= 0 ? 'used' : 'partially_used';
        $update = $pdo->prepare("UPDATE vouchers SET balance = ?, status = ? WHERE id = ?");
        $update->execute([$newBalance, $newStatus, $voucherId]);
        $insert = $pdo->prepare("INSERT INTO voucher_transactions
            (voucher_id, receipt_no, previous_balance, amount_used, new_balance, cashier_id)
            VALUES (?, ?, ?, ?, ?, ?)");
        $insert->execute([$voucherId, $receiptNo, $previousBalance, $amountUsed, $newBalance, $cashierId]);
        $pdo->commit();
        return ['success' => true, 'new_balance' => $newBalance, 'status' => $newStatus];
    } catch (Exception $e) {
        $pdo->rollBack();
        return ['success' => false, 'message' => $e->getMessage()];
    }
}
The FOR UPDATE command is important in production. It locks the voucher row during redemption so that two 
cashiers cannot spend the same balance at the same time.

13. Security and Fraud Control
Because vouchers represent money, the system must be treated like a financial module. The cashier should never 
have power to manually edit balances.
Risk Control
Voucher used twice Database transaction with FOR UPDATE and balance validation.
Cashier fraud Role restrictions and audit logs.
Fake voucher number Voucher lookup only accepts database records and can use QR 
token.
Manual balance change No direct cashier balance edit; all changes go through transactions.

13.1 Production Security Checklist
 Use HTTPS/SSL on hosting.
 Use password_hash() and password_verify().
 Use PDO prepared statements for all queries.
 Validate all amounts as positive numeric values.

 Back up database daily.
 Use role middleware on every page.
 Log every critical action.
 Keep .env outside public access.

receipt number. This is the fastest and safest route. After one or two months of successful operation, integrate it 
more deeply with the POS checkout process.
Final production formula: Company buys monthly vouchers -> Admin generates QR 
cards -> Cashier scans and redeems -> Boss sees monthly reports.
